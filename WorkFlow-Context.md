## 1. What this repository is

This is a **customized TechieFlow v4 framework** for a **solo developer** (Claude Max) shipping a portfolio of ~8–10 .NET / Blazor / MAUI apps. It is NOT an application — it is the template that gets copied into each app to drive its development with AI agents. The owner optimizes for **speed-to-market over process purity**: a stripped, opinionated subset of TechieFlow tuned for one person + AI, not the full multi-role story-by-story TechieFlow flow.

The stack the apps target: **.NET 9 / Blazor (Server | WASM | Auto) / TrBlazeUI (UI library) / TechieRag (RAG/LLM library) / optional MAUI**. Claude Code runs inside **Windows WSL** — no GUI Playwright, MAUI builds/runs on the Windows side (see `WORKFLOW.html` §0, §11).

## 2. How the framework is used (the flow)

The canonical reference for humans is **`WORKFLOW.html`** (open in a browser). The short version for an agent:

1. **Scaffold** a new app by copying this template (`scaffold-greenfield.sh` / `scaffold-brownfield.sh`) — never `npm install`. `update-framework.sh` re-syncs an existing app to the latest framework.
2. **Day-1** (`*day1-greenfield` / `*day1-brownfield` on the **analyst**): produces the 6 deliverables — Architecture, BRD, Coding-Standards, `.editorconfig`, PROJECT-STATUS, CLAUDE.md (+ checklist migration for brownfield), all HTML-rendered.
3. **`*split-brd`** (analyst): splits the rich BRD into the two requirement checklists (`<APP>-UI-Checklist.md` = `REQ-UI-*`, `<APP>-Functional-Checklist.md` = `REQ-FN/NFR/RAG-*`).
4. **Build phases:** `build-ui-phase` (trblazeui agent), `build-rag-phase` (techierag agent), `build-functional-phase` (flow-master). Each fans work out across parallel subagents by cluster, self-smokes, then **chains the verifier automatically**.
5. **Verify** (`verifier` / Vidur, `*verify ui|functional|all`): autonomously boots the app, runs Playwright + dotnet tests, writes per-REQ verdicts into the checklist **Requirements Status** tables.
6. **Handoff** (`*handoff-phase` on flow-master): usage/testing doc, status → Handoff, HTML re-render, per-library feedback consolidation.

**The owner's actual day-to-day loop** is lighter than full TechieFlow: analyst → trblazeui → flow-master → verifier, NOT story-by-story. (See session memory `feedback_custom_techieflow_workflow`.)

### Non-negotiable conventions (an agent must honor)

- **Status gate** (`.tfcore/tasks/_status-update-gate.md`): every checklist/phase-executing agent MUST end by updating `PROJECT-STATUS.md`. A phase is done when status reflects reality, not when the build is green.
- **Single source of truth** for per-REQ status = the **Requirements Status** table at the top of the owning checklist. **Never** create dated `docs/qa/*.md` or `docs/verify/*.md` files (banned).
- **HTML rendering is for HUMAN docs only.** BRD, Architecture, UsageGuide, **DevGuide**, PROJECT-STATUS render to `.html`. **The checklists NEVER render to HTML** — they are AI-agent working documents kept in markdown only (an HTML mirror of an agent doc just burns tokens and drifts). All human HTML uses the shared shell with the **light/dark theme toggle** (time-of-day default, remembered choice, warm off-white light).
- **File naming:** `<APP>` prefix on canonical docs (`<APP>-BRD.md`, `<APP>-Architecture.md`, `<APP>-UI-Checklist.md`, …). Superseded docs → `docs/OldDocs/`, never `-v2` suffixes.
- **Library feedback:** one file PER library — `docs/<APP>-TrBlazeUI-Feedback.md` (TR-NNN), `docs/<APP>-TechieRag-Feedback.md` (TR-RAG-NNN). Log gaps, work around, never silently swallow; never combine the files (separate teams).
- **Coding standards** are per-project (`docs/<APP>-Coding-Standards.md`); the field-prefix decision is per-project (e.g. AppManager uses `obj`, AstroLyfe uses no prefix). `docs/AppManager-Coding-Standards.md` + `docs/AstroLyfe-Coding-Standards.md` in this repo are **reference SAMPLES** for agents, not live docs.
- **Build invocation ladder** (`.tfcore/templates/v4custom/build-invocation-ladder.md`): solution-scan first; MAUI/iOS/Android in the `.sln` → start rung #4; workload errors (`NETSDK1178`, `Microsoft.*.Sdk missing`) mean *wrong rung*, never "build failed".

## 4. Recovering an interrupted session (`*refresh-status`)

If a build/verify run dies mid-phase — lost internet, **revoked/changed model access**, killed terminal, crashed agent — the status gate never runs, so `PROJECT-STATUS.md` is stale or wrong. Do **not** trust it. Run:

```
/TechieFlow:agents:flow-master *refresh-status <APP>        # add `verify` to also re-verify ambiguous REQs
```

It rebuilds PROJECT-STATUS from **ground-truth evidence** (the checklist Requirements Status tables + what's actually in the working tree, including source-file modification times + a fresh `dotnet build`), **refreshes the BRD §4 Development status snapshot** from those same checklists (and inserts that section into a legacy BRD that predates it — the one BRD edit it's allowed; see §5's 2026-06-14 follow-up), writes a dated `## Recovery note`, and prints the exact command to resume with. **It never runs git** — git is manual in this framework (agents never commit; the CLAUDE.md permission gate asks on `git`), so recovery reconstructs from the tables + files-on-disk + build, never commit history. It never edits source. Task: `.tfcore/tasks/refresh-status.md`; documented in `WORKFLOW.html` §8a. This exists because of the AstroLyfe incident (2026-06-13): an experimental model lost access mid-development and left no usable status.

### 2026-06-17 — Mermaid diagrams STILL erroring — real root cause found (the 2026-06-14 fix was a misdiagnosis)

Mermaid reads the `<pre>`'s `textContent` as the diagram source, so `copy` got glued onto the diagram's last line. On a **flowchart** that corrupts a node/edge id → "Syntax error". On a **sequence diagram** the trailing `copy` lands in freeform message text → still valid. **That** is why "only flowcharts broke, sequence diagrams were fine" — the signature the 2026-06-14 entry misattributed to label quoting. Reproduced the exact error and the fix in a Chrome A/B (`pre` vs `pre:not(.mermaid)`).
- **Fix:** scoped the selector to **`document.querySelectorAll('pre:not(.mermaid)')`** in `html-render-shell.md` §7 (+ explanatory comment, + the §1 feature bullet). Mermaid blocks already get copy/export from their own `.diagram` toolbar. Template only — **not mirrored** (templates load by relative path; harness mirrors cover agents/tasks only).
